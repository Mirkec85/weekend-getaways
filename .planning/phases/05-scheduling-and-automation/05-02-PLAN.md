Create `OPERATIONS.md` at the project root with these sections:

**1. Weekly Pipeline Overview**
- What: Automated flight deal newsletter sent every Thursday at ~08:00 CET
- How: GitHub Actions cron triggers `pipeline/index.ts` (fetch deals) then `pipeline/send.ts` (send emails)
- Idempotency: Both scripts check week_key — safe to re-run, second run exits cleanly

**2. Required GitHub Secrets**
Table with all 7 secrets, where to find each value, and which pipeline step uses it:

| Secret | Source | Used By |
|--------|--------|---------|
| `SUPABASE_URL` | Supabase project -> Settings -> API -> Project URL | index.ts, send.ts |
| `SUPABASE_ANON_KEY` | Supabase project -> Settings -> API -> anon/public key | index.ts, send.ts |
| `KIWI_API_KEY` | Kiwi Tequila dashboard | index.ts |
| `RESEND_API_KEY` | Resend dashboard -> API Keys | send.ts |
| `RESEND_FROM_ADDRESS` | Verified sender email (e.g. `hello@yourdomain.com`) | send.ts |
| `NEXT_PUBLIC_BASE_URL` | Production URL (e.g. `https://your-app.vercel.app`) | send.ts |
| `HEALTHCHECKS_PING_URL` | Healthchecks.io -> Check -> copy ping URL | ping jobs |

Location: `https://github.com/{owner}/{repo}/settings/secrets/actions`

**3. Kill-Switch**
- Variable: `SEND_ENABLED` (repository variable, NOT a secret)
- Location: `https://github.com/{owner}/{repo}/settings/variables/actions`
- To disable: Set `SEND_ENABLED` to `false` — next cron run skips the pipeline job
- To re-enable: Delete the variable or set to `true`
- Default (variable unset): Pipeline runs normally
- Note: Uses `vars` context because `secrets` cannot be read in job `if:` conditions

**4. Healthchecks.io Monitoring**
- Setup: Create check with period=1 week, grace=4 hours at healthchecks.io
- Success ping: Sent after every successful pipeline run
- Failure ping: Sent when pipeline job fails (appends `/fail` to ping URL)
- Alert: Operator notified if no success ping within Thursday 08:00 CET + 4 hour grace
- DST note: During DST transition weeks, both crons may fire — the second run exits cleanly via idempotency guards

**5. Keepalive**
- GitHub disables cron schedules after 60 days of repo inactivity
- `keepalive.yml` runs monthly on the 1st to prevent this
- No configuration needed — uses automatic GITHUB_TOKEN

**6. Manual Trigger**
- Go to Actions tab -> "Weekly Pipeline" -> "Run workflow" -> select branch -> click "Run workflow"
- Safe to trigger any time — idempotency guards prevent double-sends

**7. Troubleshooting**
- "supabaseUrl is required" -> SUPABASE_URL secret is missing or misspelled
- "KIWI_API_KEY is not set" -> KIWI_API_KEY secret is missing
- "RESEND_API_KEY is not set" -> RESEND_API_KEY secret is missing
- Pipeline runs but Healthchecks.io shows "Late" -> Check if the workflow was skipped (kill-switch?) or if cron was disabled (push a commit or check keepalive)
- Two runs on the same Thursday -> Normal during DST transition weeks; second run exits with "already cached" / "already sent" logs
