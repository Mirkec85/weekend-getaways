Replace the placeholder content in `pipeline/index.ts` with the full orchestrator. The file must:

1. **Load .env.local** — Copy the exact pattern from `scripts/verify-db.ts`:
   ```
   import * as fs from 'fs'
   import * as path from 'path'
   function loadEnv() {
     const envPath = path.resolve(__dirname, '../.env.local')
     if (fs.existsSync(envPath)) {
       for (const line of fs.readFileSync(envPath, 'utf8').split('\n')) {
         const match = line.match(/^([^#=\s]+)\s*=\s*(.*)$/)
         if (match) process.env[match[1]] = match[2].trim()
       }
     }
   }
   ```

2. **Import pipeline modules** (all relative, NO @/ aliases):
   - `import { weekKey, hasCachedDeals, saveDealsToCache } from './cache'`
   - `import { fetchWeekendFlights } from './fetcher'`
   - `import { selectTopDeals } from './selector'`
   - `import { enrichWithHotelEstimate } from './enricher'`

3. **`main()` async function** — the orchestration flow:
   ```
   a. loadEnv()
   b. Validate KIWI_API_KEY exists in env (throw if missing)
   c. const key = weekKey()
   d. console.log(`Pipeline running for week: ${key}`)
   e. if (await hasCachedDeals(key)) {
        console.log(`Deals already cached for ${key}. Exiting.`)
        return
      }
   f. const flights = await fetchWeekendFlights(process.env.KIWI_API_KEY!)
   g. if (flights.length === 0) {
        console.log('No qualifying flights found this weekend. Exiting cleanly.')
        return   // PIPE-04 zero-results fallback — clean exit, no throw
      }
   h. const deals = selectTopDeals(flights)
   i. const enriched = enrichWithHotelEstimate(deals)
   j. await saveDealsToCache(key, enriched)
   k. console.log(`Cached ${enriched.length} deal(s) for ${key}:`)
   l. for (const d of enriched) {
        console.log(`  ${d.destination_name} (${d.destination_iata}) — €${d.price_eur} flight + ~€${d.hotel_estimate_eur ?? 80}/night hotel`)
      }
   ```

4. **Top-level execution:**
   ```
   main().catch((err) => {
     console.error('Pipeline failed:', err)
     process.exit(1)
   })
   ```

CRITICAL: The zero-results path (step g) MUST `return`, NOT `throw`. This is PIPE-04's fallback requirement.
CRITICAL: All imports MUST be relative (`./cache`, `./fetcher`, `./selector`, `./enricher`). Do NOT use `@/` aliases.
CRITICAL: Load env FIRST before any module that reads `process.env` (the `import` of `../lib/db` inside `cache.ts` reads env vars at module load time, so `loadEnv()` must run before that import executes). Since static imports run before `loadEnv()`, the env loading in `cache.ts`'s dependency `../lib/db` will fail. To fix this: call `loadEnv()` at the TOP of the file, OUTSIDE main(), BEFORE the dynamic imports. Use dynamic `require()` calls for cache/fetcher/selector/enricher inside `main()` instead of static imports, OR move `loadEnv()` to file-level execution before the imports.

The cleanest approach: Put `loadEnv()` definition and call at the very top of the file (lines 1-10), then do static imports of pipeline modules below it. This works because Node executes the file top-to-bottom: the `loadEnv()` call runs first, then the `import` statements' side effects (which trigger `lib/db.ts` reading `process.env`) execute after env vars are set.

WAIT — actually, with CommonJS (`pipeline/tsconfig.json` has `module: CommonJS`), `import` compiles to `require()` which IS synchronous and top-to-bottom. So the pattern is:
```typescript
// 1. Load env FIRST
import * as fs from 'fs'
import * as path from 'path'
// ... loadEnv() definition ...
loadEnv()  // Execute immediately

// 2. NOW safe to import modules that read process.env
import { weekKey, hasCachedDeals, saveDealsToCache } from './cache'
// ... etc
```

This works because TypeScript with CommonJS compiles imports to `require()` calls in order.
