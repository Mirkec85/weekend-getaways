<task type="checkpoint:human-action" gate="blocking">
  <name>Task 1: Add sending domain in Resend and publish DNS records</name>
  <action>Human action required: register sending domain in Resend dashboard and publish SPF/DKIM/DMARC DNS records at your DNS provider. Claude cannot access these external UIs.</action>
  <what-to-do>
    This task requires you to complete steps in the Resend dashboard and your DNS provider.
    Claude cannot access these external UIs.

    STEPS:

    1. Sign up or log in at https://resend.com

    2. Go to Domains → Add Domain
       - Enter your sending domain (recommendation: use a subdomain like `mail.yourdomain.com`
         to isolate sender reputation from your root domain)
       - Example: if your domain is `weekendgetaways.com`, add `mail.weekendgetaways.com`

    3. Resend will show you 4 DNS records to add:
       - 1x TXT record (SPF): on `mail.yourdomain.com`
         Value: `v=spf1 include:amazonses.com ~all`
       - 2x CNAME records (DKIM): e.g. `resend._domainkey.mail.yourdomain.com`
       - 1x TXT record (DMARC): on `_dmarc.mail.yourdomain.com`
         Value: `v=DMARC1; p=none; rua=mailto:your@email.com`

    4. Log in to your DNS provider (Cloudflare, Namecheap, GoDaddy, etc.) and add all 4 records exactly as Resend specifies.
       - Cloudflare users: propagation is usually < 5 minutes
       - Other registrars: may take up to 4 hours

    5. Return to Resend Dashboard → Domains → your domain → click "Verify DNS Records"
       - All records must show a green checkmark

    6. Once verified: go to Resend → API Keys → Create API Key
       - Name it something like "weekend-getaways-prod"
       - Copy the key (shown only once)

    7. Add to your local .env.local file (create if it doesn't exist at project root):
       ```
       RESEND_API_KEY=re_your_actual_key_here
       RESEND_FROM=deals@mail.yourdomain.com
       ```
       (Replace with your actual domain and key)
  </what-to-do>
  <verify>Resend Dashboard → Domains shows all 4 DNS records with green checkmarks (SPF, DKIM x2, DMARC all verified)</verify>
  <done>Resend domain status is "Verified" and .env.local contains RESEND_API_KEY and RESEND_FROM with real values</done>
  <resume-signal>
    Type "dns-verified" when Resend shows all DNS records as verified (green checkmarks on all SPF, DKIM, and DMARC rows).
  </resume-signal>
</task>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Send test email and verify deliverability score</name>
  <action>Send a test email via Resend API to mail-tester.com and to a real Gmail address, then verify the score is 9+/10 and Gmail headers show dkim=pass, spf=pass.</action>
  <what-built>
    DNS records are now published and Resend has verified them. This checkpoint confirms the sending domain delivers to the inbox correctly before any real subscriber email is sent.
  </what-built>
  <how-to-verify>
    STEP 1 — Get a mail-tester.com address:
    1. Open https://mail-tester.com in your browser
    2. Copy the unique test email address shown (looks like `test-abc123@mail-tester.com`)
       — this address is valid for 5 minutes

    STEP 2 — Send a test email via Resend API (run this curl command, replacing values):
    ```bash
    curl -X POST https://api.resend.com/emails \
      -H "Authorization: Bearer $RESEND_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "from": "deals@mail.yourdomain.com",
        "to": ["test-abc123@mail-tester.com"],
        "subject": "Test email — SPF/DKIM/DMARC check",
        "html": "<p>This is a deliverability test for the weekend getaways newsletter.</p>",
        "text": "This is a deliverability test for the weekend getaways newsletter."
      }'
    ```
    Replace `$RESEND_API_KEY` with your actual key and the `to` address with the mail-tester.com address you copied.

    Expected response: HTTP 200 with a message ID.

    STEP 3 — Check your score:
    1. Return to https://mail-tester.com and click "Then check your score"
    2. Wait 30 seconds for the score to calculate
    3. Target score: 9/10 or 10/10
    4. If score is < 9: expand the failed checks — the most common issues are:
       - DMARC policy is `p=none` (acceptable for now, won't drop score much)
       - Missing unsubscribe link (acceptable for Phase 1 test — not a real newsletter email)

    STEP 4 — Send to your own Gmail address:
    ```bash
    curl -X POST https://api.resend.com/emails \
      -H "Authorization: Bearer $RESEND_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "from": "deals@mail.yourdomain.com",
        "to": ["your.gmail@gmail.com"],
        "subject": "Test email — inbox delivery check",
        "html": "<p>Checking inbox delivery for weekend getaways newsletter.</p>",
        "text": "Checking inbox delivery for weekend getaways newsletter."
      }'
    ```
    Replace `your.gmail@gmail.com` with your actual Gmail address.

    In Gmail: open the email → click the three-dot menu → "Show original"
    Verify these lines appear in the headers:
    - `dkim=pass`
    - `spf=pass`
    - `dmarc=pass` (or `dmarc=bestguesspass`)

    The email must land in the INBOX (not Spam or Promotions is fine).
  </how-to-verify>
