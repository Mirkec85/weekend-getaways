Create `app/api/webhooks/resend/route.ts` with a POST handler:

1. Import `NextRequest`, `NextResponse` from `next/server`, `Resend` from `resend`, `supabase` from `@/lib/db`
2. Create Resend instance: `new Resend(process.env.RESEND_API_KEY)`

**Signature verification (CRITICAL — follow exact order):**
3. **FIRST** call `const payload = await req.text()` — this MUST be the first body read. Do NOT call `req.json()` before this. The signature is computed over the exact raw bytes; any parsing/re-serialization breaks it.
4. Extract headers: `svix-id`, `svix-timestamp`, `svix-signature` from `req.headers`
5. Call `resend.webhooks.verify()` with:
   ```
   {
     payload,
     headers: {
       id: req.headers.get('svix-id') ?? '',
       timestamp: req.headers.get('svix-timestamp') ?? '',
       signature: req.headers.get('svix-signature') ?? '',
     },
     webhookSecret: process.env.RESEND_WEBHOOK_SECRET ?? '',
   }
   ```
6. Wrap in try/catch — on verification failure, return 400 `{ error: 'Invalid signature' }`

**Event processing:**
7. The `verify()` call returns a typed `WebhookEventPayload` with a `type` field
8. If `event.type === 'email.bounced'`:
   - Extract recipient: `event.data.to[0]` (to is `string[]`)
   - Update: `supabase.from('subscribers').update({ status: 'bounced' }).eq('email', recipientEmail).eq('status', 'active')`
   - The `.eq('status', 'active')` guard prevents re-processing already-bounced subscribers
9. If `event.type === 'email.complained'`:
   - Extract recipient: `event.data.to[0]`
   - Update: `supabase.from('subscribers').update({ status: 'unsubscribed' }).eq('email', recipientEmail).eq('status', 'active')`
   - Complaints mark as `unsubscribed` (not a separate status) since the subscriber explicitly marked email as spam
10. For all other event types: do nothing (but still return 200)
11. **Always return 200** `{ received: true }` for valid signatures — Resend retries on non-2xx (retry schedule: 5s, 5m, 30m, 2h, 5h, 10h)

**Error handling:**
12. Wrap the entire DB update in try/catch. If DB update fails, still return 200 (the webhook was valid; we don't want retries flooding a broken DB). Log the error with `console.error`.

**Do NOT:**
- Call `req.json()` before `req.text()` — this is the #1 pitfall from research
- Return non-200 for valid-signature events even if processing fails
- Process event types other than `email.bounced` and `email.complained`
- Expose detailed error messages in responses (security)
