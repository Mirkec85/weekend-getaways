  <files>app/api/subscribe/route.ts, app/api/confirm/route.ts, app/confirm/page.tsx</files>
  <action>
**POST /api/subscribe (`app/api/subscribe/route.ts`):**

1. Import `NextRequest`, `NextResponse` from `next/server`, `Resend` from `resend`, `supabase` from `@/lib/db`, `z` from `zod`
2. Create Resend instance: `new Resend(process.env.RESEND_API_KEY)`
3. Define Zod schema: `{ email: z.string().email(), gdpr_consent: z.literal(true) }` — gdpr_consent MUST be `z.literal(true)` to enforce explicit consent
4. Parse body with `BodySchema.safeParse(await req.json())`. On failure return 422 with `{ error: result.error.issues[0].message }`
5. Attempt insert: `supabase.from('subscribers').insert({ email }).select('id, unsubscribe_token').single()`
6. If insert fails with error code `23505` (unique violation), fetch existing subscriber:
   - If status is `active`: return 409 `{ error: "Already subscribed" }`
   - If status is `pending`: re-send confirmation email (idempotent), return 201
   - If status is `unsubscribed` or `bounced`: update status back to `pending`, reset `confirmed_at` and `unsubscribed_at` to null, send confirmation email, return 201
7. Build confirm URL: `` `${process.env.NEXT_PUBLIC_APP_URL}/api/confirm?token=${subscriber.unsubscribe_token}` ``
8. **Send confirmation email with clickable confirm link.** Call `resend.emails.send()` with:
   - `from: process.env.RESEND_FROM!`
   - `to: email`
   - `subject: "Confirm your subscription to Weekend Getaways"`
   - `html:` — construct an HTML email body that contains the confirm URL as a **clickable anchor link**. The HTML must include an `<a>` tag with `href` set to the confirm URL built in step 7. Example structure:
     ```html
     `<div>
       <h2>Confirm your subscription</h2>
       <p>Thanks for signing up for Weekend Getaways! Please confirm your email by clicking the link below:</p>
       <p><a href="${confirmUrl}">Confirm my subscription</a></p>
       <p>If you didn't request this, you can safely ignore this email.</p>
     </div>`
     ```
   - The `confirmUrl` variable is the URL constructed in step 7: `${process.env.NEXT_PUBLIC_APP_URL}/api/confirm?token=${subscriber.unsubscribe_token}`
   - This ensures the recipient sees a clickable link that navigates to the GET /api/confirm endpoint with their token
9. Return 201 `{ success: true }`
10. Wrap entire handler in try/catch — on unexpected error return 500 `{ error: "Something went wrong" }`

**GET /api/confirm (`app/api/confirm/route.ts`):**

1. Add `export const dynamic = 'force-dynamic'` at top (prevent caching per research pitfall 7)
2. Read `token` from `req.nextUrl.searchParams.get('token')`
3. If no token: redirect to `/confirm?status=invalid`
4. Update subscriber: `supabase.from('subscribers').update({ status: 'active', confirmed_at: new Date().toISOString() }).eq('unsubscribe_token', token).eq('status', 'pending').select('id').single()`
5. If error or no data (token not found or already confirmed): redirect to `/confirm?status=invalid`
6. On success: redirect to `/confirm?status=success`
7. Use `NextResponse.redirect()` (not `redirect()` from next/navigation — that is for Server Components, not Route Handlers)

**Confirmation result page (`app/confirm/page.tsx`):**

1. Server Component (no `'use client'` needed) — reads `searchParams.status`
2. If `status === 'success'`: show "Subscription confirmed! You'll receive your first deals email on Thursday."
3. If `status === 'invalid'` or any other value: show "Invalid or expired confirmation link."
4. Simple centered layout matching landing page styling
5. Link back to homepage

**Important notes:**
- Use `NextResponse.redirect(new URL('/confirm?status=success', req.url))` pattern for redirects in Route Handlers
- The `unsubscribe_token` column doubles as the confirm token per research decision (single token, safe because status guards prevent cross-flow)
