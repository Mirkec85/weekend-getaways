  <name>Task 1: Unsubscribe API route and result page</name>
  <files>app/api/unsubscribe/route.ts, app/unsubscribed/page.tsx, .env.example</files>
  <action>
**GET /api/unsubscribe (`app/api/unsubscribe/route.ts`):**

1. Add `export const dynamic = 'force-dynamic'` at top (prevent caching — this reads from DB)
2. Read `token` from `req.nextUrl.searchParams.get('token')`
3. If no token: redirect to `/unsubscribed?status=invalid`
4. Update subscriber: `supabase.from('subscribers').update({ status: 'unsubscribed', unsubscribed_at: new Date().toISOString() }).eq('unsubscribe_token', token).eq('status', 'active')` — the `eq('status', 'active')` guard ensures only active subscribers can unsubscribe (prevents pending users from being marked unsubscribed via confirm token reuse)
5. Check if the update affected any rows. The Supabase update returns data array — if empty, the token was invalid or subscriber was not active.
6. Add `.select('id')` to the update to check result. If data is empty/null: redirect to `/unsubscribed?status=invalid`
7. On success: redirect to `/unsubscribed?status=success`
8. Use `NextResponse.redirect(new URL('/unsubscribed?status=success', req.url))` pattern (same as confirm route)

**Unsubscribed result page (`app/unsubscribed/page.tsx`):**

1. Server Component — reads `searchParams.status`
2. If `status === 'success'`: show "You've been unsubscribed. You won't receive any more emails from us." with a brief "Sorry to see you go" tone
3. If `status === 'invalid'`: show "Invalid unsubscribe link. You may have already been unsubscribed."
4. Simple centered layout matching landing page and confirm page styling
5. Link back to homepage ("Changed your mind? Subscribe again")

**Update `.env.example`:**

Add `RESEND_WEBHOOK_SECRET=whsec_...` with a comment: `# Resend Dashboard -> Webhooks -> signing secret (Phase 2)`

**Do NOT:**
- Require authentication or login for unsubscribe — it must be one-click per SUB-03
- Show different behavior for already-unsubscribed vs never-existed tokens — both show "invalid" to avoid information leakage
